# How to Debug a Bug You Cannot Reproduce

<p dir="ltr" align="left"><strong>Presenter:</strong> Hooriyeh Maaleki</p>

**Session:** Talk

## Abstract

The bug happened in production. QA cannot reproduce it. It never happens on your machine. The logs are not very helpful. Restarting the service made the problem disappear. Now what? This session is about debugging when the most important debugging tool—reproducing the bug—is not available. We will explore how to investigate rare and intermittent failures using whatever evidence the system leaves behind: logs, crash data, process state, system information, timing clues, and targeted instrumentation. Instead of jumping between random theories, we will build a practical workflow for turning incomplete evidence into useful hypotheses, ruling out possibilities, and getting closer to the real root cause. If you have ever closed a bug with “cannot reproduce” while secretly hoping it never comes back, this session is for you.

Prerequisites: Basic experience with software development and debugging is recommended. Familiarity with Linux command-line tools and concepts.
